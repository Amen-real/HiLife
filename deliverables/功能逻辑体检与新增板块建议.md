## 3. 问题清单（按严重度）

### 🔴 P0-1 ·「跳过 / 结束训练」按钮点击无反应（自伤红线）

**位置**：`pages/workout/workout.wxml:209`

```wxml
<view class="pop-btn primary" bindtap="{{trainPhase === 'ready' ? 'skipTrain' : 'cancelTrain'}}">
  {{trainPhase === 'ready' ? '跳过' : '结束训练'}}
</view>
```

**根因**：WXML 的 `bindtap` **不支持 Mustache 动态事件名** —— 整个值会被当成**字面量字符串**，
点击时找不到名为 `{{trainPhase === ...}}` 的方法 → **静默无反应，且控制台不报错**。
（这条正是本项目自己记录在案的红线，全仓穷举后**仅此 1 处残留**。）

**后果（两个都是核心流程）**：
1. **准备阶段**：点「跳过」无反应 → 只能干等倒计时（`skipTrain` 实现见 `workout.js:521`，逻辑本身正确却不可达）。
2. **训练阶段**：点「结束训练」无反应 → **无法手动结束当前组计时并记录实际用时**
   （`cancelTrain` 的 `work` 分支实现见 `workout.js:529-537`；它唯一的静态绑定在 208 行，而那个按钮是 `wx:if="{{trainPhase === 'ready'}}"` → 训练阶段根本不可见）。

**修法**：挂**静态**事件名 + js 内分支（与 `pages/profile` 的 `onIdTap` 同一模式）：
```wxml
<view class="pop-btn primary" bindtap="onTrainBtn">{{trainPhase === 'ready' ? '跳过' : '结束训练'}}</view>
```
```js
onTrainBtn() { this.data.trainPhase === 'ready' ? this.skipTrain() : this.cancelTrain(); }
```
**建议同时补守卫**：`verify-*.cjs` 增加"全仓 wxml 禁止 `bind*=\"{{`"断言（1 行，永久堵住这类回归）。

### 🟠 P1-5 · 从「饮食记录」页走 AI 拍照识别 **100% 失败** —— 已修（2026-09-16 第四轮）

**症状**：饮食记录页 → 某餐「添加食物」→「AI 识别拍照」→ 拍完 → 面板**永远**显示「未能识别到食物，请换一张更清晰的图。」，识别成功也记不进任何东西。

**根因（字段口径错，两处消费方照错注释写）**：

| 位置 | 写的什么 | 服务端实际返回 |
|---|---|---|
| `pages/advice/advice.js:622` | `(r.foods \|\| []).map(...)` | **没有 `foods`** |
| `pages/advice/advice.wxml:259` | `recResult.total.calories` | **没有 `total`** |
| （已删）`pages/food-vision/food-vision.js` | `r.foods` | 同上 |
| 真源 | — | `{ name, items:[{name,weight_g,calories}], total_weight_g, total_calories, protein, carb, fat, confidence, mock }`（`server/analyzer.py:7-16` / `server/vision_llm.py:106-117`） |

因为 `r.foods` 恒为 `undefined`，`(undefined || [])` = `[]`，于是 `advice.wxml:264` 的 `recResult.foods.length === 0` **恒真** → 空态文案常驻。

**为什么之前没被发现**：`recResult.mock` 与 `recResult.note` 是**真的**在合约里，所以面板会正常显示「演示数据」提示 —— 看起来"链路通了"，只是没有食物列表。这类"半个面板是对的"最容易骗过人工测试。

**根因之一在文档**：`utils/foodvision.js` 的返回合约注释写成 `{ foods, total, note, mock, provider }`。两个页面都照着它写。**错注释比没注释更危险** —— 它把错误包装成了权威。已改为按调用路径如实描述，并写明局域网 `/analyze` **只走 CalorieScan/mock、接不到 LLM**，所以联调时看不到三大营养素是**正常**的。

**处置**：按真源**映射**成本页的展示模型（视图层写法，不是第二份口径）；合计行改为 JS 拼整串（避免缺值时渲染出「蛋白 g」这种残句）。逐项营养素服务端不给，仅当整餐只有一项时把整餐值给它（那一项就是整餐，同口径），多项时留 `null` —— **不把整餐值复制给每一行**。

## 4. 新增功能板块建议

筛选原则：**在个人主体（无支付）+ 已有云开发底座 + 主包余量紧张**这三个约束下，只做"边际成本低、结构性收益高"的事。

### A. 结构性补齐（防守 —— 不做会持续失血）

**A1 · 云数据库同步 + 自动备份｜P0｜最高优先**
- **为什么**：这是**唯一一个"不做就一定出事"**的项。当前所有数据仅存本机单键，换机/清缓存=用户资产归零，且 1MB 上限迟早触顶。
- **做什么**：`store` 落库时异步写云 DB（按用户维度），冷启动以云为准做合并；关键表先行（`trainingLogs` / `meals` / `weightRecords`）。
- **成本**：你**已经在 CloudBase 上**（云存储 + 云托管都在跑），云 DB 在免费额度内，边际成本最低。
- **验收**：清缓存重进 → 数据完整恢复；导出/导入仍作为离线兜底保留。

**A2 · 轻量埋点与"我的一周"看板｜P0｜让产品可见** ｜ ⏸ **已暂停（2026-09-16，按用户指令）**
- **为什么**：现在无法回答"拍照识别被用了几次""复盘建议真被采纳了吗"。**不能衡量的功能等于没做**。
- **做什么**：本地优先的埋点（页面 UV / 拍照识别次数与耗时 / 训练完成率 / 建议采纳率），先存本地 + 自己可见的看板，再决定是否上云。
- **额外收益**：这份数据同时是你判断"哪个新板块该继续投入"的唯一依据。
- **暂停时的状态**：`utils/metrics.js` 已建好并保留（A3 在用它的计数与聚合），但**页面访问埋点（`pv`）与看板页已撤/未建**。
  恢复 A2 时按需把 `pv` / `weekSeries` / `LOG_*` / `SG_*` 加回，并同时补 `pages/metrics` 看板页与守卫 —— **别只加一半**。

**A3 · 识别结果纠错 + 本地知识库｜P1｜控 AI 成本** ｜ ✅ **已落地（2026-09-16）**
- **做什么**：识别后允许改营养值并**记住**（下次同名食物直接命中）；置信度低时主动引导走条码/手输。
- **为什么**：直接降低按次计费的模型调用量，同时把"识别错→用户失去信任"变成"识别错→一次纠正后永久正确"。
- **落地情况**（详见 §8.7）：
  - 结果可逐项纠正（热量/蛋白/碳水/脂肪 + 名称），纠正即写入本地知识库；下次同签名识别**自动套用**并显式标出「已套用你的修正值」。
  - 低置信度（< 0.6）主动提示「数值可能不准」，并给出手动录入的说明 —— **不承诺条码**（它需要外部食物库，成本高、不在本轮范围）。
  - **成本杠杆落在「饮食记录」页已有的手输表单上**（不另造第二份表单）：输入食物名命中知识库即零模型调用，并明确提示「未消耗 AI 识别次数」。
  - 本轮**顺手修好了这个功能的两个前置缺陷**（P1-5 饮食页识别恒失败、P2-7 死页），否则"识别→纠错"根本没有可用的输入端。

### B. 留存钩子（进攻 —— 让记录变成习惯）

**B1 · 里程碑与成就体系｜P1**
- 现状已有 `dateRange.streakFromDates`（连续打卡）与 `keyActionPicks`（关键动作）。
- **升级方向**：连续 N 天 / 单动作破个人纪录 / 累计容量里程碑 → 徽章墙。**复用已有数据，几乎零新增数据模型**。

**B2 · 训练分享卡（图片）｜P1｜个人主体下最现实的增长手段** ｜ ✅ **已落地（2026-09-16）**
- 个人主体不能做社交关系链，但**图片分享不受限**。
- 现状 `onShareAppMessage` 是空实现（P2-4）—— 这是**最低成本的从 0 到 1**：训练完成态生成一张带数据的卡片。
- **落地情况**（详见 §8.8）：`utils/shareCard.js`（纯逻辑，可 `node` 直跑）+ 复盘页「生成本场分享卡」→ canvas 出图 → `wx.showShareImageMenu` 发好友 / 存相册兜底。
  - 落地页选**训练复盘**：它是「完成态」唯一的自然聚集点，且已有本场全部数据。
  - **Non-goal：朋友圈**（单页模式把交互页打残，见 P2-4）。

**B3 · 训练提醒（真实现）｜P2**
- 若决定保留「训练提醒」开关（P0-2），需走订阅消息：申请模板 + 服务端定时触达。**成本不低、且受类目与模板审核约束**，建议排在 A 之后。
- 替代方案：**本地化提醒**（不做推送，改为"上次训练已 N 天"的首页提示），零审核成本。

### C. 差异化（做厚产品，但都建立在 A 之上）

### 8.3 P0-1 收口：用户质疑引出的三项修正（2026-09-16）

第一轮修完之后，用户提出一个关键质疑：**「跳过是跳过 5 秒准备倒计时，结束训练是结束当前训练计时 —— 这个逻辑不对吗？」**

**文案那侧的 Mustache 正常编译**（所以真机上「跳过」「结束训练」两个词都显示正确，看起来一切正常），但 `bindtap` 的属性值不按数据绑定编译 → 整串沦为字面量事件名 → 匹配不到任何方法：不报错、不警告、点了没反应。所以当时的现象与计时逻辑无关。修复后的接线与用户描述的语义**完全一致**：

| 准备（5s） | 取消 | `cancelTrain` | 清表并关闭，不记录、不标记 |

| 训练中（60s） | 完成本组 | `cancelTrain` | 停表 → 记实际时长 → `completeSet` → 弹休息 |

#### 本轮真正值钱的发现：守卫的「内部调用」判定被骗过

`verify-event-binding.cjs` 的 `[D]`（孤儿方法）在**收紧之前一直是绿灯**，因为它判断「是否被内部调用」用的正则是 `\.<name>\b`。本意是匹配 `this.xxx`，但它同时命中了**别的对象上的同名方法**：

```js
// pages/plan/plan.js（旧）
_deletePlan(id) {
  wx.showModal({ success: (res) => { ... store.deletePlan(id); ... } });  // ← 这一行
},
deletePlan(e) { ... },   // ← 从未被 wxml 绑定，是死方法
```

`store.deletePlan` 与 `deletePlan` 撞名 → `[D]` 认为它"已被内部调用" → 一个死方法藏了整整一轮。

**这与 §8.4 的 `verify-exercises-compact` 是同一类失效**：守卫没坏、退出码是 0，只是它**量的不是它以为在量的东西**。两次的修法也一致 —— 光改实现不够，必须配**校准样本**，否则下次有人放宽正则，绿灯依旧：

```js
[D0] 孤儿判定自检（校准样本：this. 前缀被放宽回 \.name 时这里会先红）
  · 真内部调用 this.foo          → 必须判为「被调用」
  · 只有 store.foo（同名不同对象） → 必须判为孤儿
  · this.foo(...) 带前缀          → 必须判为「被调用」
```

顺序很关键：**先修守卫 → 跑一次确认它终于报出 `deletePlan` → 才动手删**。反过来做（先删再修守卫）就永远证明不了修复有效。

并且 `[D0]` 自己也被探针测过（`_probe-d0.cjs`）：把 `this.` 前缀打回 `\.name` → `[D0]` 红、且 `[D]` 重新漏掉 `deletePlan`；还原 → 重新报出。**校准块本身也不许是恒绿的装饰。**

#### 顺带修掉两类"改了 A 却漏了 B"

- **`server/README.md` 指引用户去改一个已删除的文件**（`utils/caloriescan.js` 的 `backendUrl`）。这类漂移比代码 bug 更耗人 —— 照着文档做的人会先怀疑自己。
- **`ARCHITECTURE.md` 把某台开发机的瞬时局域网地址写成了"项目开发期后端"**。文档和代码一样不该收录内网拓扑。

#### 一条口径：空配置必须"说得出口"

`visionBackendUrl` 留空后，若 `analyzeByUpload` 直接 `cfg.url.replace(...)`，会发出 `wx.uploadFile({ url: '/analyze' })`（相对地址）→ 失败回调只回一句「请求失败」。
**配置缺失属于"可预见的用户错误"，必须在代码里被翻译成人话**（`未配置视觉识别后端地址：…该配哪一项、生产该走哪条链路`），而不是让它退化成一个网络异常。

**P2-9 · 对比度门禁有系统性盲区（是漏报，不是误报）**

实测（**就地改原声明**做探针，不是追加同名规则 —— 后者可能被"只取首个声明"掩盖）：

|---|---|---|
| `.an-text { color:#1A1A1A }` 压 `.analyzing { background:#0A0A0A }` | **1.09:1** | 仍报「深色下无对比度缺口」 |
| `.r-note { color: var(--text-weak) }` 压 `--n-50` | **2.44:1**（浅色） | 仍报「浅色下无对比度缺口」 |

→ **本轮只报不改**：修它等于把全仓次级文字从 `#A0A0A0` 整体压深，是设计可见的改动、涉及 10 个文件，该由你定。**A3 新增的文字已一律避开该 token**（用 `--n-700` / `--accent-ink`）。
→ 门禁修法建议（另行排期）：候选条件放开为「能解析出纸底的规则都算」；解析不出纸底的**显式计入「未覆盖」计数并打印**，而不是静默跳过。

### 8.8 B2 落地：训练分享卡（2026-09-16 第五轮）

> 指令：**做 B2 分享卡**。附带清掉 P2-4（`onShareAppMessage` 空实现）。

#### 为什么分享卡是这个阶段唯一正确的增长动作

- 个人主体做不了社交关系链（§6 Non-goals 已钉死），但**图片分享不受主体限制**。
- 它是**唯一一个零新增数据模型**的增长手段：完成度、时长、容量、个人纪录全部已在 `trainingStats` 里算好，这轮只是把它们**画出来**。

#### 架构：把「出图」拆成三段纯函数，让守卫可以穷举

`utils/shareCard.js` **不 require `wx`、不 require `store`**（`[F]F4` 钉死），因此能在 `node` 里直跑任意数据：

| 段 | 函数 | 产物 |
|---|---|---|
| 算 | `buildModel({log, logsDesc, idx})` | 只含标量的模型（可直接断言） |
| 排 | `layout(model)` | 一组 `{t:'rect'\|'circle'\|'line'\|'text'}` 指令，**每条 text 自带 `bg`（它压着什么颜色）** |
| 画 | `draw(ctx, model)` | 把指令翻成 canvas 调用 |

价值在于：**对比度与越界都在纯数据上验完** —— 不需要截图、不需要真机。canvas 截图在 CI / 命令行里根本拿不到，靠截图验收等于这项功能没有门禁。

#### 口径：一个数字都不许在这张卡上重算

| 卡上的东西 | 唯一真源 | 守卫 |
|---|---|---|
| 训练量 | `stats.fmtVol` | `[C]C1` |
| 时长 | `stats.durationSecOfLog` | `[C]C1` |
| 破纪录集合 | `stats.sessionRecords` | `[C]C5` |
| 行上「比上次 ↑x%」 | `stats.sessionChip` | `[C]C6` |
| 单位格式化 | `stats.fmtW` / `stats.fmtVol` | `[F]F1` |

顺带**消掉两份重复实现**：`fmtW` / `fmtVol` 原本在复盘组件与「我的」页各有一份，`buildRecords` 的排行逻辑原本写在组件里 —— 全部上收到 `trainingStats.js`，调用方改成一行委派（`[F]F1~F3` 防止被抄回来）。
⚠️ 这是每次抽共享 util 都会重现的现象：**其它套件里「盯着实现」的断言会集体变红**，按原意改指新真源，不是删断言。

**卡上的两处细节口径**（都不是随手写的）：
- 纯自重场次 `vol === 0` → 训练量位改为**总次数**（显示「0 kg」是把有效训练说成没练）。
- 未记录 RPE → 显示 `—`，**不是 `0/10`**（`0` 是一个事实陈述，而这里的事实是「没测」）。

#### 两处「诚实」决定

1. **不做朋友圈（不加 `onShareTimeline`）。** 朋友圈打开的落地页是**单页模式** —— tabBar 不渲染、路由与多数交互接口被禁用。`pages/list` 是日期筛选 + 抽屉的交互密集页，分享进去就是又一个「诚实的残废入口」（本仓已删过一个同类）。要发朋友圈得另做纯内容页，不是加个钩子就能成立。
2. **拿不到分享 API 时不假装成功。** `wx.showShareImageMenu` 需基础库 ≥ 2.14.3。低版本上**不静默失败**，而是弹说明 + 给出「保存到相册」这条真实可走的路（`saveImageToPhotosAlbum`）；相册权限被拒则引导 `openSetting`，用户取消不打扰。

#### 配色：卡片是「会离开 App 的图」，所以不跟主题

分享卡固定用**浅色品牌配色**，不跟随深色主题。理由：图会落在别人的聊天窗口里，收图人的环境不由本机主题决定 —— 跟随主题只会让**同一场训练在不同主题下产出两张不同的图**。

配色逐对验了对比度（`[A]`）：

| 组合 | 对比度 |
|---|---|
| 主文字 `#0A0A0A` on 暖白底 `#F7F7F5` | 18.46:1 |
| 主文字 `#0A0A0A` on 白卡 `#FFFFFF` | 19.80:1 |
| 亮绿底 + 深字 `#0A0A0A`（全库铁律） | 16.74:1 |
| 次级字 `#444444` on `#F7F7F5` | 9.08:1 |
| 上升 chip `#4C7300` on `#F1F5E6` | 5.04:1 |
| 下降 chip `#C4363B` on `#FBEDEB` | **4.68:1（全表最小）** |

全部 ≥ AA 4.5。**并且刻意避开 P2-9 的盲区色 `--n-500` `#A0A0A0`（压浅底仅 2.44:1）** —— 门禁看不见它，所以在这张卡上先用硬断言拦住（`[A]A4`：配色表不许含该色）。块边界同样过了 Δ≥10 的硬线（白卡 vs 暖白底 Δ=10、边框 vs 白卡 Δ=27、chip vs 白卡 Δ=17/25）。

#### canvas 的两个坑（都写进守卫）

1. **backing store 固定 750，不乘 dpr。** 卡是「设计稿 rpx 口径」的定宽物：乘 dpr 只会让不同机型导出**不同**的图，还会撞上导出尺寸上限。
2. **离屏画布不能用 `opacity:0` 藏**（原生组件会在真机泄漏），也不能 `display:none`（拿不到 node 尺寸）。正解 = `position:fixed; left:-2000px` + 显式 CSS 尺寸，出图后由 `wx:if` 卸载。`[F]F6` 钉死这两条。

#### 落地页与失败路径

- 入口在**训练复盘**（`components/training-review`）：它是「完成态」唯一的自然聚集点，且本场数据已全部在 `logsDesc` 里。
- 交互：`openShareCard` → 生成中态 → 出图后展示，长按可用微信原生图片菜单（`show-menu-by-longpress`），另给「发送给朋友 / 保存到相册」两个按钮。
- **失败路径逐条断言**（`[E]`）：拿不到画布节点 / 导出失败 / 无场次 / 无分享 API / 用户取消 / 相册权限被拒 —— 每种都验「弹层关没关、`busy` 归没归位、提示对不对、有没有留下半成品图」。

#### P2-4 之外还修了什么

`pages/review` 补上 `onShareAppMessage`。这不是顺手，而是**必要**：它既是分享卡图片的**扫码落地页**，也是朋友转发的默认落地路径 —— 它自己不声明分享，入口就会退化。

#### 守卫工程经验：第三次踩同一个坑的变体

| 位置 | 现实约束 | 确认的落法 |
|---|---|---|
| 朋友圈 | 微信**没有**「一键发朋友圈」开放接口；唯一相关的是 `onShareTimeline`，而它走**单页模式**（tabBar 不渲染、多数交互接口被禁）—— 交互密集页加它就是残废入口，本项目刻意不加 | 当轮落成**独立的「存相册发朋友圈」通道**（存相册 + 引导文案），并明说不谎称「已分享到朋友圈」；**第八轮已推翻**：`wx.showShareImageMenu` 的转发面板本身就能发朋友圈 ⇒ 该通道删除，见 §8.11 |

#### 版式（对齐参考图）

单列竖排四段：**身份行**（文字头像首字 + 昵称 + 右侧「N 天 连续训练」）→ **一句话结论条**（浅绿底 + 左侧亮绿竖条）→ **主视觉**：前/后双视图解剖图 + 两侧肌群标签（引线指向肌群包围盒中心，主练肌群加粗）+ **右列三指标**（消耗估算 / 总重量 | 总次数 / 总耗时）→ **逐动作卡**（动作名 + 比上次 chip + 逐组胶囊，最好的一组用亮绿实底）+ **个人纪录条**（只在本场真破纪录时出现）。

底层是**三段式纯函数**：`buildModel` → `layout`（产出带 `bg` 的 ops）→ `draw`。主视觉走 `bodymap.bodyPaths()` 的**纯路径**，卡内**零图片资源** —— 版式/对比度/越界因此能在 node 里穷举断言，不必靠真机截图。

**新增三个开关，都落在内容模型上**（不是只存布尔值）：隐藏训练内容（`showActions=false`）、合并当天（同日多场合成一张，结论改「共 N 场」）、样式（浅色/深色两套调色板，**不跟随 App 主题** —— 图片会离开 App 落在别人聊天窗口里，跟随本机主题会让同一场训练产出两张不同的图）。

#### 本轮踩的坑（按危害排序）

1. **⚠️ 真事故：临时产物写在仓库根，把主包撑爆 3.5MB。** 预览用的 `_sharecard-ops.json`（1.4MB）+ 十几张 PNG 落在仓库根，而 `.png` / `.json` 都不在 `packOptions.ignore` 里 ⇒ `scan-main-package.cjs` 报「5622 KB / 2048 KB，超出 3574 KB —— 提审会被拒」。**修法不是删文件了事**：把两个工具的产物改到 `scripts/_out/`——`scripts` 本就是 folder 级忽略目录，产物从此**按构造**进不了包。
2. **`Object.keys(Set)` 恒为 `[]`。** 模型里的 `anatomy` 一开始返回 `{front: Set, back: Set}`，既 `JSON.stringify` 不出内容（Set 变 `{}`），也让守卫拿到空对象。改成**排序后的数组**（`buildModel` 的返回值全部是标量/数组 ⇒ 可 JSON 往返，守卫才断言得动）。
3. **演示数据「恰好打平」导致一条分支永远跑不到。** `sessionRecords` 判破纪录是 `本场最佳容量 > 历史最佳`，而演示数据里卧推与上一场**恰好都是 405** ⇒ 正确地不算破纪录，但也意味着**预览图里永远看不到纪录条**。补一个专造破纪录的用例（45kg×8 > 40kg×8），并**故意让它的 `logsDesc` 不含打平的那场**——`recordBoard` 取的是所有更早场次的最大值，混进去会把这次的纪录压掉。
4. **断言基线写错，比出来的不是想验的东西。** 「有纪录条的卡片更高」一开始拿「1 个动作 + 纪录条」跟「5 个动作的常规卡」比高度 —— 量到的其实是动作行数差。改成拿**同一个模型**去掉 `pbs` 前后比，并断言高度差恰好等于「纪录条高 + 卡间距」。
5. **声明值与渲染值不一致。** 纪录条 `h=56` 却声明 `r=CARD_R=32`，而 `roundRect` 会静默夹到 `28`（渲染没问题，但结构检查永远说不清「圆角是否超过半高」）。改成 `r = min(CARD_R, PB_H/2)`，让声明本身是诚实的。
6. **`NaN` 会让越界判据静默变绿**（`NaN` 参与比较恒为 `false`）。引线端点若算出 `NaN`，原来的「引线必须落在自己那一栏」判据会**直接放过**。补一条显式的有限性断言 + 一条校准（把后视引线人为右移 700 必须被抓）。
7. **假警报：把合法的深色用法判成违规。** 断言「亮绿当字色时只准压 `#0A0A0A`」在深色板上红 —— 深色板把亮绿用作「上升 chip」的字色（压深绿底，对比度很高，是**合法且正确**的）。判据改成「亮绿当字色时**对比度 ≥ 7**」——这既挡住「亮绿字压浅底（≈1.05:1，字直接消失）」，又不误伤深色板的正确用法。**假警报比漏报更糟**，改判据而不是关掉它。

### 8.10 训练结束出口：三选一确认卡（2026-09-16 第七轮）

#### 起因

用户要求：「训练完成按钮增加选项『完成并生成分享图』『完成训练』『取消』，参考 <分享卡.png>」。参考图是 iOS 健身 App 的三选一确认弹窗：徽章 → 标题 → 副标题 → 中段信息块 → 蓝色主按钮 → 两行文字按钮。

#### 改前的两个问题

| 位置 | 改前 | 改后 |
|---|---|---|
| 主出口 | 顶栏「完成训练」**直接保存**（全部完成时）/ 弹系统确认框（有未完成组时）——「练完顺手生成分享图」这个最高频动作要绕两次：回训练 tab →「我的 → 训练日志」→ 分享 | 一张卡三个有名字的出口，**一次直达** |
| 确认语义 | 弹的是系统框的「确定」，没告诉用户「即将保存什么」 | 副标题给剩余组数 + 摘要给三项事实（已练 / 完成组数 / 完成动作），**用户不必凭记忆决定按哪个** |

#### 三个出口的真实落法

- **完成并生成分享图** → `saveWorkout(actions, 'share')`：走**同一条**保存路径（不另写落库逻辑），差别只在保存后的去向 —— `redirectTo('/pages/review/review?share=1')`。
  为什么是 `redirectTo` 而不是 `navigateTo`：本页此刻已 `_finished` + 会话已清，留在栈里只会让用户从复盘页返回时看到**一张空的训练页**；`redirectTo` 用复盘页**替换**它，返回键直达训练 tab。
- **完成训练** → `saveWorkout(actions)`，`navigateBack()`，与改版前完全一致（1000ms toast 停留不变）。
- **取消** → 只关卡片；不保存、不冻结会话（全局计时继续走，可继续练）。

**登录门禁的关闭时机也调整了**：`showFinishCard: false` 移到 `saveWorkout` 内、`auth.requireLogin()` 之后 —— 未登录时什么结果都没发生，卡片就不该凭空消失（原来在调用方先关，会出现「弹了登录框 + 弹窗自己没了」）。

参考图中段是 iOS 的「写入 Apple 运动健康」开关（带勾选框）。**本 App 没有这条能力**，按项目红线（UI 每个开关必须能追溯到一条真实能力调用）不摆假开关 —— 那个位置换成本场摘要。参考图的版式照搬、参考图的能力不照搬。

#### 顺带发现并修掉的一个真机 bug（深色主题）

`.rest-pop-emoji.solid` 是**写死的品牌亮绿** #C8FF00 徽章，里面的奖杯用 `.ico--ink`（= `var(--text)`）。深色块把 `--text` 翻成 `#FFFFFF` ⇒ **白字形压亮绿 ≈1.6:1，真机上那个奖杯直接看不见**。

这不是卡片新引入的，是组间休息「训练完成」态就一直躺着的存量缺陷 —— 而它恰好是「亮绿底配墨字」这条铁律的**镜像陷阱**：铁律只说了「绿底必须用墨字」，没说「墨字是怎么来的」。正解：

```css
/* 绿底与主题无关 ⇒ 字形也必须与主题无关 */
.rest-pop-emoji.solid .ico { background-color: #0A0A0A; }
```

特异性 `(0,3,0) > .ico--ink` 的 `(0,1,0)`，不需要 `!important`。新增守卫 `verify-icon-contrast.cjs [H]`：亮绿实底容器必须有显式的后代规则把字形钉回墨色 —— 因为已有的 `[D]`（「深色下 `ico--ink` 必须翻白」）恰好会**要求**造成这个伤害的翻转。

#### 新守卫 `verify-workout-finish.cjs`（58 断言）

这条链路跨三个文件（workout 页 → review 页 → training-review 组件），**每一段都能静默失败**，所以每段都钉：

- `[A]` wxml：三个出口都是静态事件名；**顺序 = 完成并生成分享图 → 完成训练 → 取消**（顺序即优先级，与参考图一致）；摘要走 `wx:for` + 唯一键。

- `[C]` 三个出口的行为（stub `Page`/`wx` 跑**真实**方法）：取消不落库不跳转；完成训练落库 + `navigateBack`；完成并生成分享图落库 + `redirectTo` 到 `share=1`；**未登录不落库且卡片不消失**。
- `[D]` 复盘页接线：`share=1` → `autoShare` → 组件**一次性**自动开分享卡。这里的关键设计是**信号只消费一次**（`_wantShare` 置位 → 开出即清），因为组件 `pageLifetimes.show` 每次回前台都会 `rebuild`；不消费就会「用户关掉卡片，切回来它又弹」。两条到达路径（属性观察器 / `attached` 读 `data.autoShare`）都要覆盖 —— 基础库两条顺序都有可能。

### 8.11 分享卡弹层收口：通道删一条 + 「取消」不再被遮挡（2026-09-16 第八轮）

#### 用户报的两件事

> 「训练复盘页的生成本场分享卡弹窗底部取消按钮被遮挡；分享给朋友可以直接跳转到微信朋友圈，所以存相册发朋友圈按钮不需要」

第二句是**能力判断**，不是审美偏好 —— 它推翻了 §8.9 定下的「朋友圈通道 = 存相册 + 引导」。

#### ① 删掉「存相册发朋友圈」：通道数 = 能力数

删之前先对齐了一下：那条通道的处理器 `saveMomentsShareCard` 与「保存到相册」的 `saveShareCard` **逐行相同**（都是 `_saveToAlbum(path, ...)`），唯一差别是成功后多弹一个 modal 讲「微信 → 发现 → 朋友圈 → 从相册选这张图」。

而 `wx.showShareImageMenu` 打开的**就是微信原生的图片转发面板** —— 面板里本来就有「分享到朋友圈」。于是那条通道里**没有一个是它独有的能力**：保存是重复的，引导是多余的。

> **口径**：通道数 = 真实能力数。同一个能力开两个入口，用户会以为它们是两件事；而「多一个入口」在数据上还会把一次保存行为拆成两种，反而看不清。

**连带清理**（不清理就是死代码 / 死绑定）：
- `.sc-ch` 从 3 个 → 2 个；`saveMomentsShareCard` 处理器删除。
- 图标 `.ico-moment-sc`（mask data-URI，本组件内重复定义、不共享 `styles/icons.wxss`）随之删除。
- 原来只有两条通道时若沿用 `flex: 1` 平摊，两个图标会落在 1/4 与 3/4 处、中间空出近 240rpx（看着像少了第三项）⇒ 改 `justify-content: center` + 固定列宽 200rpx + `gap: 140rpx`。
- 说明文字从「朋友圈需存到相册后自行发布」改为「点『分享给朋友』，在转发面板里可直接发到朋友圈」—— 路径变了，文案必须跟着变（红线：文案只写实现得了的事）。

#### ② 「取消」被遮挡：两个独立成因，一次都堵掉

**成因 A（真凶）：宿主页有自定义 tabBar 时没让出底栏高度。**
组件同时挂在**「数据」tab**（`pages/list`）与**复盘页**（`pages/review`）。自定义 tabBar 是**框架级固定层**，页面内 `z-index` 调到 2000 也压不住。组件里另一个弹层（关键动作抽屉 `.ka-mask` / `.ka-sheet`）早就用 `with-tab` 处理过这件事，**分享弹层漏了** —— 同一个组件里同一类 bug 只修了一半。

**成因 B（隐患）：抽屉总高没有上限。** 注释里写着「总高控制在 100vh 内」，但那是**算出来的经验值**，不是 CSS 上限。预览图是 `50vh`（随屏高走），文案一长 / 小屏一挤，「取消」就会被顶出屏幕，届时**只剩点遮罩一条退路**。

修法：

```css
.sc-sheet { max-height: calc(100vh - 96rpx); }              /* 顶部留 96rpx：遮罩仍可见，用户才知道能点空白关 */
.sc-sheet.with-tab { padding-bottom: calc(88rpx + 44rpx + env(safe-area-inset-bottom)); }  /* 与 .ka-mask.with-tab 同口径 */
.sc-preview { height: 50vh; min-height: 220rpx; flex: 0 1 auto; }   /* 唯一可压缩项 */
/* 开关 / 通道 / 说明 / 取消 一律 flex-shrink: 0 —— 压缩只能发生在预览图上 */
```

`with-tab` 由运行时探测（复用既有的 `_hasTabBar()`，每次 `openShareCard` 重新探一次，不写死）：拿不到页面栈或探测抛异常都兜底为 `false` —— 最坏只是少留白，不会误伤复盘页。

#### 把「为什么这么改」写成可执行的算式

这次没有靠真机截图自证，而是把版式模型搬进了守卫 `verify-share-card.cjs [J]`：按 `1rpx = vw/750` 复算两个真实机型（375×667 无安全区 / 375×812 安全区 34）×两种状态，**先证明坏样本确实是坏的**：

| 状态 | 「取消」被底栏盖住 | 结论 |
|---|---|---|
| 无 `with-tab` | **30 / 44 px**（两个机型都是） | 这就是用户看到的「被遮挡」，尺子能看见 |
| 有 `with-tab` | 0 px | 完整可见 |

同时断言 `sheet ≤ 100vh - 96rpx`（上限生效）与 `preview ≥ 220rpx`（不塌成 0），另加 `J12`：模型里的常量（`50vh` / `88rpx` / `96rpx`）必须与 CSS 同源，并配一条「改掉 50vh 后判据会报错」的校准 —— 否则改了 CSS 而模型没改，`J11` 会开始骗人。

#### 本轮踩的工具坑（值得单独立规矩）

**⚠️ 并行编辑同一个文件会静默丢改动。** 同一批里对同一文件发两条编辑，后一条基于旧内容落盘，把前一条**悄悄覆盖掉**，而工具**两条都回报成功**。本轮因此丢了 3 处改动（`.sc-tip` / `.sc-cancel` 的 `flex-shrink`、`data.scTabSafe`），是靠独立探针逐点复核才发现的 —— **四处守卫全绿也没发现**，因为丢的是「刚加的东西」，没有任何既有断言会盯它。

**规矩**：同一个文件的多处改动**必须串行**；改完用独立探针逐点复核，别只看工具回报。
