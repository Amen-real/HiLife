# B1 训练提醒订阅消息推送 — 简单 PRD

## 1. 项目信息

- **Language**：简体中文
- **Programming Language**：微信小程序原生（WXML/JS），云开发（定时触发云函数）；沿用现有 `cloud1-d0g5ihto42b4ed256` 环境
- **Project Name**：hilife-b1-subscribe-reminder
- **小程序**：衡砺健身记录（个人主体，AppID wx0d4d9fe07646ea15）
- **原始需求复述**：在已有站内提醒（v2，`utils/reminder.js` 单源：开关、时刻档位 [18,19,20,21]、catchup 判据、连续未练文案分级、站内横幅）基础上，新增微信订阅消息推送——用户授权后，云端定时给「今天没练」的用户下发「服务通知」卡片，点击卡片跳回小程序训练页，实现人不在小程序也能收到提醒。

## 2. 平台约束与已定决策（必须如实遵守）

1. **个人主体仅一次性订阅消息**：授权一次 = 攒 1 条发送额度，发完即止。用户在弹窗勾选「总是保持以上选择，不再询问」并允许后，后续每次调用授权接口**静默成功并再攒一条**（无弹窗）。因此授权调用必须挂在高频自然动作上（开启提醒开关时、完成训练时），效果 ≈ 长期订阅。**授权弹窗必须由用户主动点击触发**（平台红线）。
2. **云端只存提醒专用最小事实**：openid、提醒开关、档位、订阅额度、最后训练日期（+更新时间）。这是提醒功能专用数据，**不是**训练数据全量云同步（1.0 决策不变）。`privacy.wxml` 必须同步新增云端数据说明；存量守卫 verify-profile 的 C10 禁词扫描范围扩展到该文件。
3. **订阅消息模板**：需在小程序后台用公共模板库申请（个人主体可申请公共模板，不可自建类目模板），模板 ID 部署时配置，代码留占位。
4. **文案红线**：禁用「训练日」一词（本仓已被占用为模板 A/B/C 日）；文案只承诺做得到的事（如「按你选的时刻提醒，可能因微信授权额度需要偶尔重新确认」）。
5. 触达形态：微信聊天列表「服务通知」卡片，点击直达小程序指定页面。
6. **额度耗尽**：静默不发 + 站内横幅引导补授权（不弹窗骚扰）。

## 3. 产品目标

1. **离线可达**：用户当天未练习时，在所选时刻收到微信服务通知卡片，点卡片一步回到小程序对应页面。
2. **额度可持续**：通过「高频动作静默续额度」机制，让一次性订阅在体验上接近长期订阅，且补授权引导不骚扰。
3. **数据最小化**：云端只落提醒所需最小事实，不破坏「训练数据只存本机」的 1.0 决策，隐私说明同步透明。

## 4. 用户故事

1. 作为开启提醒的用户，我想在点击「开启提醒」时看到微信授权弹窗并允许，这样之后即使不在小程序里也能收到提醒。
2. 作为完成训练的用户，我想在记录完成时系统静默续上 1 条订阅额度（无感知、无弹窗），这样额度不会因为我常来练习而耗尽。
3. 作为今天没练的用户，我想在我选定的时刻（如 19:00）收到一张服务通知卡片，内容包括温和的提醒文案，这样我能记起今天该练了。
4. 作为收到卡片的用户，我想点击卡片直接落到小程序训练页，这样一步就能开始今天的练习。
5. 作为额度耗尽的用户，我不想被打扰——云端静默不发，但我下次进入小程序时看到一条站内横幅引导我点一下补授权。
6. 作为关闭提醒的用户，我想关闭后云端不再给我下发任何卡片，且我的云端提醒记录被停用（额度可保留或清理，见待确认）。

## 5. 需求池

### P0（最小闭环）

| # | 需求 | 说明 |
|---|------|------|
| P0-1 | 授权攒额度入口 | 「开启提醒」开关点击时触发 `requestSubscribeMessage`（用户主动点击，平台红线）；授权成功即攒 1 条额度。文案遵守红线（无「训练日」，只承诺可做到的事） |
| P0-2 | 完成训练静默续额度 | 训练完成提交动作上同样挂授权调用（配合「总是保持以上选择」即静默成功再攒一条） |
| P0-3 | 云端提醒档案 | 新建云函数/云数据库集合，存最小事实：openid、提醒开关、档位、订阅额度计数、最后训练日期、更新时间。开关/档位/训练完成时同步上报 |
| P0-4 | 定时下发云函数 | 定时触发（建议每 15–30 分钟一档扫描 18/19/20/21 四个档位时刻），筛选「开关开 + 到达档位时刻 + 今天最后训练日期 < 今天」的用户，消耗 1 条额度下发订阅消息 |
| P0-5 | 点击回跳 | 卡片点击跳转到小程序指定落地页（默认训练页，待确认） |

| P0-7 | 隐私说明同步 | `privacy.wxml` 新增云端提醒数据说明段落；verify-profile C10 禁词扫描范围扩展至该文件 |

## 6. UI 说明

- **授权入口**：不加新页面。① 提醒开关（设置/提醒区域）点击「开启提醒」时弹微信原生授权弹窗——此为用户主动点击触发，合规；② 训练完成页/完成动作上静默调用（无 UI，弹窗仅在未勾选「总是保持以上选择」时出现）。
- **卡片（微信侧）**：服务通知卡片，文案温和（沿用站内分级文案基调可精简为单级），字段遵循所选公共模板的固定结构；点击落地页默认训练页。
- **额度耗尽引导**：进入小程序时在现有站内横幅位展示「提醒额度已用完，点这里补一条」，点击触发授权；用户可「稍后再说」，逻辑复用现有横幅交互，不新增打扰。
- **隐私页**：`privacy.wxml` 新增「提醒功能会在云端保存：提醒开关、提醒时刻、剩余提醒次数、最近一次练习日期」等说明。
- **文案红线自检**：所有新增文案不含「训练日」；只承诺「按你选的时刻提醒，可能因微信授权额度需要偶尔重新确认」级别的可兑现内容。

## 7. 范围外（本 PRD 不动）

- 站内横幅既有逻辑（v2 判据、文案分级、「稍后再说」交互）不变，仅新增额度耗尽引导这一种横幅内容。
- 视觉识别链路（云托管 hilife-vision）不动。
- 训练数据本机存储的 1.0 决策不变，不做全量云同步。

## 8. 待确认问题（需用户拍板）

1. **卡片落地页**：跳训练页还是首页？（建议：训练页，一步到位）
2. **下发判据**：云端是否也吃 catchup（今天没排课但本周未达 weeklyTarget 也推），还是只推「今天有安排没练」？catchup 需要云端多存每周安排/目标的最小事实。（建议：先只推「今天有安排没练」，catchup 留 P2）
3. **关闭提醒后的云端记录**：额度计数保留还是随开关关闭一并清理？（建议：保留额度，仅停用下发，用户重开即恢复）
4. **删除小程序/清数据后**：云端档案无本机对应，额度自然耗尽即停；是否需要额外清理策略（如 30 天未活跃自动清）？（建议：不做额外清理，额度耗尽即自然失效）
5. **公共模板选型**：用户申请哪个公共模板（字段结构决定卡片文案上限），需在申请前共同确认。
