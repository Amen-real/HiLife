# HiLife 深色主题对比度体检报告

> 生成方式：`node scripts/verify-dark-theme.cjs`（门禁）/ `node scripts/scan-dark-token-gaps.cjs`（明细）
> 判定底座：`scripts/lib/dark-contrast.cjs`（真实 WCAG 计算，不是「token 有没有翻转」的启发式）
> 状态：2026-09-15 **两侧通道均已清零**，门禁已把浅色通道一并升为硬失败。

## 一、结论

| 通道 | 结果 |
|---|---|
| [A] 深色文字对比度 | **0 缺口**（合格 125 处 / 豁免 51 品牌亮底深字 / 11 处源码内声明豁免） |
| [B] 浅色面 token 未翻转（白卡） | **0 处** |
| [E] 浅色侧对比度 | **0 缺口**（原 22 处已清，见第四节） |

## 二、本轮修正的真实缺陷

### 2.1 深色回归（「硬编码色 × 会翻转的 token」错位）——4 处

这类是最阴的：规则本身两种主题共用，但一侧写死、一侧用 token，切主题后两者反向跑。

| 位置 | 症状 | 修法 |
|---|---|---|
| `action-detail .hero .badge` | `color: var(--white)`；`--white` 在深色下是**卡面色** `#161616` → 压在恒定深色遮罩上 **1.05:1**（隐形） | 改字面 `#FFFFFF`（徽章永远叠在演示图 + 深色 scrim 上，与主题无关） |
| `food-vision .btn-all` | `background: var(--text)`（深色翻白）配写死的 `#fff` 字 → **1.00:1** | 字色改 `var(--card)`，与底色成对翻转 |
| `list .date.active` | 底 `var(--n-900)`（深色翻白）配写死的 `#A6C24A` 橄榄绿 → **2.01:1** | 新增深色覆盖：品牌亮绿底 + `var(--primary-ink)` 墨字 = 16.74:1；`has-record` 小圆点同步翻墨色 |
| `profile .dtile-ic` | 底 `var(--card)`（深色 `#161616`）配写死的 `#0A0A0A` 字形 → **1.09:1** | 基线字色改 `var(--text)`；亮绿实底的 `.dtile-ic-b` 就地给墨色 |

### 2.2 深色通道对比度不足——3 条规则（6 处，含宿主重复）

根因是**同色系淡底 + 同色系字**，直接把 `--error` / `--warning` / `--accent-deep` 当字色用：

| 位置 | 浅色 | 深色 | 修法 |
|---|---|---|---|
| `advice .mock-tip` | 1.68:1 | 1.68:1 | 字色改 `var(--accent-ink)`；深色块补 `--accent-ink: #FFC08A` + `--warning-tint` 翻深底 |
| `training .exercise .del` | 3.38:1 | 3.91:1 | 字色改 `var(--danger-text)`；深色块补 `--danger-text: #FF6B70` |
| `training .sel-op.del` | 3.39:1 | 3.39:1 | 底 `var(--error)` 改 `var(--danger-solid)`（白字 5.33:1） |
| `workout .wo-set-no.warmup` | 2.69:1 | 3.87:1 | 字色改 `var(--accent-ink)`；深色块补 `--accent-ink` |
| `training-review .pa-chip.down` | 3.75:1 | 3.88:1 | 字色改 `var(--danger-text)`；**宿主页** list / review 的深色块补 `--danger-text` |

### 2.3 口径单源：`--danger-text` 从计划页升为根 token

原实现只在 `plan.wxss` 里定义 `--danger-text`（浅 `#C4363B` / 深 `#FF6B70`），
属于「单页私有正确解法」—— 别的页面各写各的，于是全踩 2.9~3.9:1 的坑。
现升到 `app.wxss` 根，并新增恒定红实底 `--danger-solid`（配白字 5.33:1）。
绿档同理补 `--success-text`（浅 `#4C7300` / 深 `#C8FF00`）。

### 2.4 补记：「选择器带 `.theme-dark`」≠「token 已翻转」（`workout` 动作菜单）

这是第二轮才发现的，比上面的都严重，且**分析器当前抓不到**。

`workout.wxml:363` 的 `.exmenu-mask` 是 `.page` 的**根级兄弟节点**（`</view>` 在 360 行收掉了 `.page`），
所以它拿不到 `.page.theme-dark` 上的变量继承。页面确实把深色 token 写在了一组选择器里：

```css
.page.theme-dark,
.rest-mask.theme-dark,
.hist-mask.theme-dark,
.repl-mask.theme-dark { --n-900: #FFFFFF; --text: #FFFFFF; ... }   /* 漏了 .exmenu-mask */
```

三个 mask 都列了，唯独漏了 `.exmenu-mask`。而它又有一条硬编码：

```css
.exmenu-mask.theme-dark .exmenu-pop { background: #161616; }   /* 底被压成深色 */
```

结果就是**深底 + 浅色 token 的字**：

| 元素 | 深色下取到的值 | 对比度 |
|---|---|---|
| `.exmenu-t`（菜单项文字） | `--text` → 根值 `#0A0A0A` | **1.07:1**（看不见） |
| `.exmenu-title`（"替换动作"标题） | `--text-sub` → 根值 `#444444` | **1.86:1**（看不见） |
| `.exmenu-ic`（左侧图标底块） | `--bg` → 根值 `#F1F1EE` | 深色里冒出一块浅灰 |

**修法**：把 `.exmenu-mask.theme-dark` 补进那组选择器，并删掉多余的硬编码底色（`--card` 现在会正确翻成 `#161616`）。

#### 为什么分析器没报

它判断「深色侧」的依据是**选择器里有没有 `.theme-dark`**，而不是「这个 token 赋值在这棵子树里到底生不生效」。
带 `.theme-dark` 却没有对应 token 声明的节点，会被它当成已经翻转 —— 与「组件靠宿主页供给变量」是同一类盲区。

要真正自动拦住，需要按 **wxml 的 DOM 层级** 去求「元素祖先链」与「token 声明所在选择器组」的交集，
而不是靠类名推断。当前 `hostPagesOf` 只处理了组件 → 宿主页这一种跨作用域情形，节点级联没覆盖。

## 三、11 处「声明式豁免」的写法

静态分析算不出来的纸底，**不允许**在脚本里藏白名单。改为在 CSS 源文件中就地声明：

```css
/* @contrast-ok: 纸底是 .rest-pop.dark —— 计时弹窗是固定深色卡（#161616，不随主题翻转），
   所以「半透明白胶囊 + 白色系字形」在两种主题下都成立；静态推算因类名无前缀关系而误用页面底色。 */
.pop-pill { ... }
```

- 只作用于**紧跟其后**的那一条规则（避免一条注解吞掉下面几条）。
- 覆盖两类：① 纸底非 CSS 面（相机取景画面、`.video-mask` 全屏遮罩、固定深色弹窗）；② WCAG 明示豁免（`disabled` 控件、条件渲染的空字形）。
- 原因可 review、可 grep，新增缺口若不写原因，门禁照旧拦。

## 四、浅色侧对比度（原 22 处，已清）

深色通道清零后暴露出这批**浅色（默认主题）**的历史低对比。首次登记为 15 处；修正分析器的大字判定口径（见第五节第 4 条）后，实际为 **22 处 + 1 处双主题失败**，按根因收敛：

| 处数 | 根因 | 修法 |
|---|---|---|
| 8 | `--n-600` 压 `--n-100`/`--bg` = **4.38:1**（差 0.12 过关）：`list .eh-chip`、`plan .plan-tag`/`.pd-close`/`.tpl-tag`/`.tpl-close`/`.tpl-desc`、`weight-record .change-chip` 等 | 改用 `--n-700`（8.46:1） |
| 5 | `--n-500`/`--text-weak` 压浅灰底 = **2.31:1**：`weight-record .date-chip`、`workout .hist-delta`、`training-review .pa-chip.flat`(×2 宿主) | 改用 `--n-700` |
| 5 | 语义绿当字色压绿淡底 = **2.86~3.02:1**：`training-review .pa-chip.up`(×2 宿主)、`training .exercise .body .tag`、`action-detail .title-block .tag`、`plan .pd-act-idx`/`.tpl-act-idx` | 新增根 token `--success-text: #4C7300`（5.0~5.3:1），深色侧各页翻 `#C8FF00` |
| 4 | 语义红 `#F2545B` 当字色压红淡底/白底 = **2.93~3.39:1**：`weight-record .change-chip.up`、`workout .hist-delta.up`/`.exmenu-ic.danger-ic`/`.wo-del-btn`/`.wo-set-del` | 换 `var(--danger-text)`（4.6~5.9:1） |
| 1 | 缩略图播放键 scrim `rgba(0,0,0,.5)` 在近白底图上只到 **3.95:1**：`favorites .play` | scrim 提至 `.58`（5.33:1） |

两点值得单记：

- **`--success-text` 是本仓既有设计的欠账**，不是新发明。`app.wxss` 那段注释本来就把 `--success` 列为「当字色压淡底会低到 1.7~3.4:1」的问题案例，并为此建了 `--danger-text`，绿档一直没补上。
- **`.wo-set-del`（删组 ✕）原本两侧都不过**（浅 2.97:1 / 深 4.42:1），被「粗体就算大号字」的口径整个豁免掉，此前从未被报出来。

清完后门禁已把浅色通道一并升为硬失败。

## 五、分析器自身修过的四个坑（否则永远是狼来了）

历代审计之所以漏掉上面这些缺陷、又同时误报一堆，是工具链的问题：

1. **把「同一元素的基础类」当父容器**：`.tk-tag.done` 以 `.tk-tag` 开头，于是拿 `.tk-tag{background:var(--primary)}` 当纸底，算出「亮绿压亮绿 1.00:1」的假结论。
   → 判据改为「前缀之后必须紧跟组合符（空格/`>`/`+`/`~`）」。
2. **忽略 `.page.theme-dark <同一选择器>` 覆盖**：项目大量深色修法是直接给同选择器写覆盖（如 `.pool-check`、`.exercise .body .tag`）。
   → 新增 `darkOverrideOf`，深色侧按覆盖后的底/字算。
3. **纸底非 CSS 面时硬猜**：相机、视频遮罩、固定深色弹窗上的元素被当成压在页面底色上。
   → 改为 `@contrast-ok` 显式声明，把「算不出来」变成「作者写明」。
4. **「大字」判定过宽（前三个是误报，这个是漏报）**：旧口径「非粗体 ≥42rpx **或只要 `font-weight:700`**」把 20~26rpx 的粗体小标签一律按 3.0:1 放行 —— 于是 `.tpl-tag`(4.38:1)、`.wo-set-del`(2.97/4.42:1) 等 **7 处真缺陷静默通过**。漏报比误报危险：误报会让人去核对，漏报直接给假的安全感。
   → 改为 WCAG 2.1 SC 1.4.3 的口径「≥24px（48rpx）常规 或 ≥18.66px（≈37rpx）粗体」；字号写成 `var(--fs-*)` 时查根 token 再折算，避免把真大号字当正文误伤。

**还没修、但已知的同类盲区**：「选择器带 `.theme-dark`、实际却不在 token 覆盖选择器组里」的情况，分析器仍假定 token 已生效 —— 本次靠人工读 wxml 层级才发现。详见 **2.4 节末尾**。

## 六、怎么跑

```bash
node scripts/verify-dark-theme.cjs                 # 门禁：两侧通道 0 缺口才算过
node scripts/verify-dark-theme.cjs --report-light  # 只看深色通道；浅色侧降级为报告
node scripts/check-dark-contrast.cjs               # 人工精选点（带成因批注，防「照报告做正确的事却砸坏对比度」）
node scripts/scan-dark-token-gaps.cjs              # 明细报告，含每条的底/字与两侧对比度
```
